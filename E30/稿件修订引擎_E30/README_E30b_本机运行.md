# E30b 本机运行顺序（2026-10-09）

E30b 规则（作者确认）：
1. 分析单位为病例（消融住院），不区分首次消融和重复消融。
2. 基线分级均取自同次住院 TTE 报告：
   - 电子档案能导出的，用文本解析分级；
   - 未能导出的，用课题组补录到研究登记表的分级；
   - 登记表二尖瓣、三尖瓣分级均为空白 = 无基线心超；
   - 有 1 个月心超的登记住院，以登记分级为准。
3. 无电子报告、又无 1 个月心超的登记住院不纳入。
4. 不再做报告可得性加权和敏感性分析。

结果：配对反应分析集（844 次）全部包含在基线表型集内，流程为单一主干。

## 运行步骤

先把本目录的 `63_baseline_phenotype_analysis.py`、`74b_E30b_case_flow_and_S1B.py` 复制到 `05_统计代码/可移植版/顶刊修订/`。其中 63 号脚本覆盖原文件，原文件请先备份。然后在项目根目录依次运行：

```
python3 05_统计代码/可移植版/顶刊修订/63_baseline_phenotype_analysis.py      # R48_A–H（基线集）
python3 05_统计代码/可移植版/顶刊修订/66_AFtype_two_cohorts.py base           # R50_A（S11 A 部分）
python3 05_统计代码/可移植版/顶刊修订/72_table_by_AFtype.py                   # R55_B/C（Table 1）
python3 05_统计代码/可移植版/顶刊修订/74b_E30b_case_flow_and_S1B.py           # R59_A–D（流程图、S1B）
```

## 运行时请留意屏幕输出

- `E30b baseline set (cases)`：基线集病例数、两种分级来源的构成、配对手术在基线集中的个数，以及未分型的 AF 例数。
  - 若未分型数 > 0，这些病例需要按既定规则补充分型。原补充只针对每例的首次消融住院，现在纳入的重复消融住院和补录病例可能缺少分型。
- `paired procedures overall / matched to archive list`：登记表 844 次中，按病案号匹配到消融住院清单的个数。17 号脚本显示有 1 次病案号缺失，若为 843，这一例需要手工补匹配。
- `1-month TTE but not in paired set (check)`：理论上应为 0，不为 0 请告诉我。
- `registry LVEDD column`：若显示 not found，补录病例的左室舒张末径只能取自电子报告。
